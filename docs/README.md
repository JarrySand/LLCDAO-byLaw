# docs/

定款・各規程そのもの（リポジトリ直下の `01_`〜`05_`・`appendices/`）ではなく、その**周辺ドキュメント**を整理する場所です。完成度・用途に応じて **stock（安定参照）** と **flow（作業中）** に分けて管理します。

## 構成

```
docs/
├── README.md                  # この説明書
├── stock/                     # 安定参照：完成度が高く、継続的に参照する資料
│   ├── guide/                 # 運用ガイド（設計思想・構成・立上げ・運用）
│   │   ├── context.md         # 設計思想（共通原則・前提・トレードオフ）
│   │   ├── structure.md       # 構成・参照関係・版管理
│   │   ├── setup/             # 立上げガイド（Setup）
│   │   ├── operation/         # 運用ガイド（Operation）
│   │   └── ...
│   └── 緊急時対応規定まとめ.md  # 緊急時対応の整理
└── flow/                      # 作業中：特定の改訂・検討のためのワークスペース
    ├── teikan-revision/       # 定款改訂プロジェクト（ver3.x）
    └── 規程整合-ver3.3/        # 規程類を定款ver3.3に整合させる修正（今回の作業）
```

## stock / flow の考え方

- **stock（ストック）**：完成度が高く、長期にわたって参照する安定資料。運用ガイド、緊急時対応のまとめなど。
- **flow（フロー）**：特定の改訂・検討のための作業資料。差分分析、ドラフト、整合性チェック、修正記録など。区切りがついたら、必要な成果を stock やリポジトリ直下の正式文書へ反映する。

## 置き場所の目安

- 恒常的に参照する設計思想・手順 → `stock/guide/`
- 特定バージョン対応や一時的な検討・記録 → `flow/<ワークスペース>/`
- 作業が完了し安定したら、要点を stock 側へ昇格させる

## ワークスペースの例（flow/規程整合-ver3.3/）

「規程類を定款ver3.3に整合させる修正」の作業一式。①→②→③の3段ロジックで構成：

- `01_定款差分_ver2.0_to_ver3.3.md` — 定款2.0→3.3の差分（規程に波及する構造変更・条番号対応表）
- `02_規程影響ポイント_ver3.3.md` — 差分により変更が必要になった規程類のポイント（影響の洗い出し）
- `03_修正実施ポイント_ver3.3.md` — 実際に変更を加えたポイント（修正記録・3周レビュー・残課題）
